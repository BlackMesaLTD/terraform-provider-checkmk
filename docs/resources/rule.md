# checkmk_rule (Resource)

Manages a CheckMK rule. Rules control monitoring behavior through conditions and values. Requires activation. **Important:** Label rulesets (host_label_rules, service_label_rules) cannot use label conditions to avoid circular dependencies.

## Example Usage

```terraform
# Basic rule example: Set host check interval
# This rule configures 60-second check intervals for production hosts

resource "checkmk_rule" "check_interval" {
  ruleset = "extra_host_conf:check_interval"
  folder  = "/"

  # Simple numeric values can be passed as strings
  # For the check_interval ruleset, the API expects a float
  value_raw = "60.0"

  properties = {
    description = "60-second check interval for production"
    comment     = "Managed by Terraform"
    disabled    = false
  }

  conditions = {
    host_tags = [
      {
        key      = "criticality"
        operator = "is"
        value    = "prod"
      }
    ]
  }
}
```

## Schema

### Required

- `properties` (Attributes) Rule properties including description, comment, and disabled status. (see [below for nested schema](#nestedatt--properties))
- `ruleset` (String) The ruleset name (e.g., 'extra_host_conf:check_interval', 'custom_checks', 'host_label_rules').
- `value_raw` (String) The rule value as a raw string. Format depends on the ruleset. For simple values, use the string directly (e.g., '60'). For complex values, use JSON encoding.

### Optional

- `conditions` (Attributes) Conditions that determine when this rule applies. All specified conditions must match (AND logic). (see [below for nested schema](#nestedatt--conditions))
- `folder` (String) The folder path where the rule will be created. Default is '/' (root folder). Path delimiters can be `~`, `/`, or `\`.

### Read-Only

- `api_id` (String) CheckMK's internal UUID for the rule. Used for updates and deletes.
- `id` (String) Computed hash based on ruleset, description, and conditions. Used for identity.
